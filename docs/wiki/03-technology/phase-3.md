## Checked in opencode's documentation

Checked on 2026-11-13 by a research agent that read the pages below and ran read-only commands on opencode 2.3.0. The documentation at `https://opencode.ai/docs/` is the one for version 2: its index, `https://opencode.ai/docs/llms.txt`, is titled "OpenCode V2 Documentation", and the pages for version 1 are under `https://opencode.ai/v1/docs/`. Quotes are from the documentation.

### N7 — the rules in every session

- opencode loads `~/.config/opencode/AGENTS.md`, then every `AGENTS.md` from the working directory up. "OpenCode V2 recognizes `AGENTS.md` only. It does not use `CLAUDE.md` as a fallback." ([instructions](https://opencode.ai/docs/instructions/))
- The configuration key `instructions` adds files: "Use the `instructions` array to add files, glob patterns, or HTTP(S) URLs alongside discovered `AGENTS.md` files". An absolute path is "Used as written" and a `~/` path is "Resolved from your home directory". "Configured instructions load after `AGENTS.md` files, in the order they are listed." "Missing files are skipped." (same page)
- A plugin can add text to the system prompt of each model call with a `context` hook, or put an entry in a session's instructions; the types of the second are named `Experimental`. ([server plugins](https://opencode.ai/docs/build/plugins/server/))

| Way | Meets N7? |
|-----|-----------|
| One `instructions` entry in the global `opencode.json` with the path of `plugin/rules.md` in this repository | Yes. The file is read in place, so there is no copy. If the repository moves, the file is skipped without an error |
| `~/.config/opencode/AGENTS.md` as a link to `plugin/rules.md` | Not known: whether a linked file is followed is not documented. It also takes the one global file a person may want for their own instructions |
| A plugin of the product that adds the text with a hook | Yes, but it is code to maintain against an interface with no stated stability, for what one line of configuration does |

### N8 — the skills

- Folders searched: "Global: `~/.config/opencode/skills`", "Global compatibility: `~/.claude/skills`, `~/.agents/skills`", "Project: `.opencode/skills`", "Project compatibility: `.claude/skills`, `.agents/skills`". ([skills](https://opencode.ai/docs/skills/))
- More folders: "Add more local directories or HTTP catalogs with the `skills` array in any `opencode.json` or `opencode.jsonc`". An absolute path is "Used as written". "`skills` arrays are combined rather than replaced." Entries of that array have the highest precedence. (same page)
- "The file path determines the skill ID. The frontmatter `name` is only a display label." A skill of this product would be `prepare-project`, without the `playbook:` prefix Claude Code adds.
- "All frontmatter is optional at runtime." "skills without [a description] are not advertised". At each model step the list holds "only the ID, name, and description, not the full Markdown body".
- "Existing skill frontmatter and Markdown bodies do not require a V2 rewrite." ([migration](https://opencode.ai/docs/migrate-v1/))
- The skills of a Claude Code plugin are not read: none under `~/.claude/plugins` appeared in the list opencode resolved on this machine. So the product's installation in Claude Code does not reach opencode by itself.

### N9 — the agents and their models

- An agent is a Markdown file at "`~/.config/opencode/agents/<name>.md`" or "`.opencode/agents/<name>.md`". "Frontmatter accepts the same fields as an `agents` configuration entry. The Markdown body becomes the agent's `system` prompt". ([agents](https://opencode.ai/docs/agents/))
- Fields, from the published schema `https://opencode.ai/config.json`: `model`, `request`, `system`, `description`, `mode`, `hidden`, `color`, `steps`, `disabled`, `permissions`. No other field is allowed, so the `tools` and `effort` lines of a Claude Code agent file do not belong in an opencode one.
- "`model` uses `provider/model` with an optional `#variant`". There is no field for effort: "Variants are named options for one model, often used for reasoning effort or token budgets", and "an unknown variant produces a model-resolution error". ([models](https://opencode.ai/docs/models/))
- `mode` "accepts `primary`, `subagent`, or `all`. When omitted on a new custom agent, it defaults to `primary`".
- A read-only agent is made with `permissions`, an ordered list where "The last matching rule wins"; the documentation's example denies the actions `edit` and `shell`.
- Delegation: "`subagent` starts a child session with a configured subagent." "Subagents run with fresh context in their own child sessions." ([tools](https://opencode.ai/docs/tools/))
- opencode has its own built-in subagents `general` and `explore`.
- No configuration key points to a folder of agent files outside the three locations. An agent can also be written as an entry of `agents` inside `opencode.json`, and a configuration value can read a file: "Use `{file:path/to/file}` to substitute the contents of a file". ([config](https://opencode.ai/docs/config/))

Because the two tools take different front matter, one agent file cannot serve both.

Tried on opencode 2.3.0 on 2026-11-13, in a temporary project folder outside this repository, reading the result with `opencode debug agents` and `opencode api GET '/api/skill?location[directory]=<folder>'`. No model was called.

|-------|--------|
| A project's `.opencode/agents` as a link to a folder elsewhere | Followed: the agent files in the linked folder were listed, with their model and body |
| A project's `.opencode/skills/<name>` as a link to a skill folder elsewhere | Followed: the skill was listed |
| A custom agent file named `explore` | It replaces the built-in `explore`: one agent with that ID, with the custom description, model, and body |

### N10 — a review in a context that did not write the change

- A skill has no field that runs it in a separate context. The documented front matter of a skill is `name`, `description`, `metadata.opencode/autoinvoke`, and `disable-model-invocation`.
- A subagent runs "with fresh context" (N9), so a review done by the `review` agent is in a separate context.
- A command can run in one: "Set `subagent: true` to run a command in a background child session", with an `agent` field. ([commands](https://opencode.ai/docs/commands/))

### N12 — installation

- Global configuration is `~/.config/opencode/opencode.json` or `opencode.jsonc`; on this machine neither exists. A project's configuration overrides the global one. ([config](https://opencode.ai/docs/config/))
- `opencode plugin add` takes an "npm registry or Git package specifier" and does not take a local path. A local plugin is a folder named in the `plugins` array or placed under `~/.config/opencode/plugins/`. ([plugins](https://opencode.ai/docs/plugins/))
- A plugin is code: it registers skills and changes agents through functions. Nothing documents a plugin that ships `skills/` or `agents/` folders of Markdown, and "V1 plugin implementations do not run in V2".

So opencode has no equivalent of the Claude Code plugin that TD1 uses. What N7 and N8 need is a few lines in one global configuration file.

With TD13, TD14, and TD15 an installation is three things on a person's machine: two entries in `~/.config/opencode/opencode.json` (`instructions` and `skills`, each with a path into the clone of this repository) and one link, `~/.config/opencode/agents`. `opencode reload` "Reloads configuration without restarting the server".

| Way | Meets N12? |
|-----|------------|
| The steps are written in this repository's README and done once by the person, as the two commands of Claude Code are (TD1) | Yes. Nothing to build or maintain. Three manual steps, and a mistake in a path is silent (N7), so the check of N13 must be run afterwards |
| A shell script of the product writes the two entries and the link | Partly. One command, but it must merge JSON into a file the person owns, in plain shell (TD2), and it is a command-line tool of the product's own, which D40 excludes |
| A plugin of the product, installed with `opencode plugin add` from this repository's git address | No. A plugin cannot add an agent (the documented interface has no way to add one), and it is code against an interface with no stated stability |

### N14 — MCP servers

- "A local server is a command that OpenCode starts over the MCP stdio transport. Add one with a command after `--`", as in `opencode mcp add <name> -- <command>`. "Add `--global` to make it available in every project". In the file a server goes under `mcp.servers`. ([MCP servers](https://opencode.ai/docs/mcp-servers/))

How the three servers are connected to Claude Code on this machine, read from `~/.claude.json` on 2026-11-13: `codegraph serve --mcp`, `engram mcp --tools=agent`, and `npx -y --package=@upstash/context7-mcp@2.2.5 -- context7-mcp`, all over stdio. Engram 3.7.1 also has `engram setup opencode`, which installs "an agent plugin", and CodeGraph has `codegraph install` with opencode among its targets (`engram setup --help`, `codegraph --help`). Whether either writes what opencode version 2 reads is not verified: version 2 does not run plugins written for version 1, and it moved servers under `mcp.servers`.

| Way | Meets N14? |

### N15 — other skills opencode reads

For this repository opencode 2.3.0 resolved 43 skills on 2026-11-13: 3 built in, and the rest from `~/.claude/skills/` and `~/.agents/skills/`, including the folders nested under `_old/` and `synced/`. The condition of D111 holds for `~/.agents/skills/`.

`~/.claude/skills/` holds five skills that are not the product's (`hyperframes`, `hyperframes-cli`, `hyperframes-registry`, `media-use`, `reverse-any-video`) and that Claude Code uses. D111 does not cover them, and they stay visible in opencode (D113). No switch turns the two compatibility folders off; what is documented is a permission rule per skill, where `deny` "Hides matching skills from the model and rejects loading".
