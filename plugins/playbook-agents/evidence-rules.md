# Evidence

The general rules of the playbook, one row per kind, learned from repeated findings of `review`. Rules come here by the owner's approval (repeated-corrections-20); `evidence.sh` reads this file with the project's `docs/wiki/evidence.md`.

## Kinds

| Kind | Level | Rule | Applies when | Source | Scope |
|------|-------|------|--------------|--------|-------|
| change-contradicts-rule-of-another-page | 2 | Before a step writes in a page whose format another page defines, read that format page and check every value the step writes against it: headings, fixed values, required cells, and where the record lives. Example: a step that records a row in a table whose format page fixes the allowed values of a column must write one of those values, not a natural-language answer the check refuses. | A skill, migration, or repair step writes in pages whose format another page or check defines | 4 reviews, 2026-11-14 to 2026-11-19, in the playbook repository | general |
| check-ignores-how-tool-reads | 2 | Verify a setting the way the consuming tool reads it: parse the file it loads, take the key, the event, the matcher or condition, and the path the command really uses, and check that this entry, not another one, makes the behaviour happen. A substring found in the file proves nothing. Example: a check that a commit hook is set must read the entry's own matcher and condition under its event, so narrowing that condition fails the check even when another hook holds the same text. | Code reports that a setting, hook, or config entry is in place | 4 reviews, 2026-11-13 to 2026-11-17, in the playbook repository | general |
| check-passes-when-nothing-checked | 2 | Make a check fail, not pass, when it examined nothing, found no target, met a missing input it needs, or ran a tool that reported an error; count each of these as a failure with its own message. Example: a wiki check whose folder is a symlink it does not follow, or whose `grep` exits 2 on a file name starting with a hyphen, must fail and say so, not pass with nothing reported; pass `--` before file names. | Code reports success after scanning, matching, or counting something in files | 4 reviews, 2026-11-14 to 2026-11-17, in the playbook repository | general |
| decided-behaviour-changed-without-decision | 2 | Before a change or a fix alters what a written decision or an accepted plan states (a text, a list, an order, a mode), find the decision, then either keep its behaviour or ask the owner and record a decision that names both, and update the pages and the tests together. The tests must not assert the new behaviour while the decision still states the old one. Example: a hook whose decided prompt reads "push, pull requests, and merges" must not ship "push, pull requests, merges, and releases" until the owner chooses the new text and it is recorded as a decision that replaces the old one. | A change or a fix touches behaviour that a decision, a plan unit, or an architecture page of the work states | 3 reviews, 2026-11-18 to 2026-11-20 | general |
| definition-stated-in-two-files | 2 | State a definition, rule, or requirement in one file only, and make every other file that needs it point to that file; before adding a line to a skill, reference, or agent, check that no file loaded in the same context already says it. Example: a skill line that repeats a rule of the contract loaded every session is deleted, not reworded. | A change adds or moves a definition, rule, or requirement in a file loaded together with others | 3 reviews, 2026-11-16 to 2026-11-17, in the playbook repository | general |
| documentation-contradicts-code | 2 | When a change adds or alters a check, a command, an exit code, or a variant, find every comment, header, and page that states its scope or effect, and make each statement true for every variant the code has; a test must not make a known gap the expected result. Example: a header that says "exit 1 when a command fails" is wrong when the script exits with the command's own code; fix the code or the header, and check that the code does not collide with another documented one. | A change alters what a check, command, hook, or script does, or how far it reaches | 5 reviews, 2026-11-16 to 2026-11-17, in the playbook repository | general |
| failure-leaves-partial-state | 2 | When a step writes in several moves, make a failure or an interruption at any point leave what was there before: write to a temporary file and move it into place, set a `trap` that removes what this run created, apply the irreversible move last, and clear leftovers of an earlier killed run at the start. Example: a mark command that saves the old marker must remove that saved copy on success, on failure, and at its next start, so no copy outlives a run. | Code writes files, folders, or settings in more than one step and can fail or be killed midway | 4 reviews, 2026-11-13 to 2026-11-17, in the playbook repository | general |
| identifier-not-unique | 2 | Build an identifier used to count or dedupe from parts that tell any two items apart and stay the same on every run: keep the full precision of a time, give a missing part a value taken from the item itself, never a shared default, and never depend on file or read order. Example: two reviews called in the same second, or both undated, get the call's own id as a suffix, not `#2` by order. | Code derives an identifier used to count, dedupe, or match items across runs | 3 reviews, 2026-11-19 to 2026-11-19, in the playbook repository | general |
| instructions-contradict-each-other | 2 | After writing or changing a step, read it against every rule and limit of its own file and of the files it is loaded with, and against the steps before and after it, and make them agree: order (propose before acting), scope (where it may write), and stop conditions (a stop must not skip a later step that has to run). Example: a step that stops when nothing is ready to consolidate must not come before a step that runs either way; move the stop or make the later step independent of it. | A skill, a reference, or an agent's instructions are written or changed | 6 reviews, 2026-11-14 to 2026-11-19, in the playbook repository | general |
| missing-test | 2 | Give every guard and failure path its own case: each exit code, a missing dependency, a failed write, the cleanup of old files, the input variants the reader must tolerate (CRLF, a header without its trailing pipe, rows inside a fenced code block, a value above a bound), and a second repository or worktree when a key includes the root. Example: a hook that exits 0 when its shared library is missing needs a case that removes the library; without it, deleting that guard makes the shell exit 2 and block the call while every test passes. | Code adds or changes a branch, a guard, a cleanup, or a failure path | 9 reviews, 2026-11-14 to 2026-11-19, in the playbook repository | general |
| pattern-broader-than-format-field | 2 | Match a field with a pattern that accepts only what the format defines for it, anchored to its position and bounded at both ends, and test it against the other content the format allows there. Example: "No findings." counts only as a whole line, not inside a sentence; `git merge` must not match `git merge-base`; a date must be a real day, not the 31st of February; a file name needs word boundaries, so a longer name does not count. | Code decides what a cell, line, token, or command is by a pattern | 7 reviews, 2026-11-16 to 2026-11-19, in the playbook repository | general |
| reference-to-undefined-target | 2 | Point only to a page, step, list, or workflow that exists where the instruction runs, with a default when it may be missing, and write a step's result before the last check that covers it. Example: a reference that defers building to a workflow defined by another plugin must say what to do when only this plugin is on. | Instructions refer to another page, step, output, or workflow | 3 reviews, 2026-11-14 to 2026-11-17, in the playbook repository | general |
| required-field-has-no-place | 2 | When a step requires writing a value, check that the format of the table or page it goes into has a place for that value, and add the column or field in the format page in the same change. Example: a step that sets a task to Done with its date needs a date column in the progress table that another page defines, for every kind of task. | A step requires recording a value in a table or document whose format is defined elsewhere | 3 reviews, 2026-11-14 to 2026-11-17, in the playbook repository | general |
| rerun-ignores-recorded-state | 2 | Before asking or writing, read what earlier runs recorded: decisions, overrides, delegations in force, and proposals already declined; skip what is settled and record a refusal so it is not proposed again. Example: a close step that proposes delegations reads the delegations in force and the declined proposals first, and proposes only the rest. | A skill or script can run again where an earlier run already made and recorded choices | 3 reviews, 2026-11-16 to 2026-11-19, in the playbook repository | general |
| test-passes-when-broken | 2 | Before calling a behaviour tested, remove or break it in a copy and see its test fail, then restore it. Make the test pin exactly what its name says: the field that holds each text, the output stream, the hook event, every direction or side (a rename into and out of a folder, the installed and the available version), and parse structured output instead of matching a fragment. Example: a test named "runs only on startup" must fail when the command is also added to the group with no matcher, which runs on resume, clear, and compact too. | A test or an eval grader is written or changed | 15 reviews, 2026-11-14 to 2026-11-19, in the playbook repository | general |
| unexpected-input-value-unhandled | 2 | For every value read from a file or another tool, list the forms it can take, the valid ones in every syntax the format allows and the malformed or unknown ones, and give each a defined path: parse it, or fail or report it by name. Never let an unknown value fall into the path of a known one. Example: a format marker of `0`, `-1`, or `valid` must be reported as malformed, not read as "no marker" nor sent to a reference that does not exist; a YAML field must be read with CRLF, quotes, and multi-line values, or rejected. | Code or instructions branch on a value read from a file, a marker, front matter, or another tool's output | 5 reviews, 2026-11-14 to 2026-11-17, in the playbook repository | general |
